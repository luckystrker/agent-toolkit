## Пайплайн разработки (agent-toolkit)

Карта: требования размыты → **grilling** → **spec-to-checklist** → реализация (**tdd**) → **acceptance** (тестировщик → критик → гейт) → коммит (гейт-хук) → **handoff** в конце сессии. Сбоку по необходимости: **research** (первоисточники), **code-review** (ревью диффа по двум осям).

Правила конвейера:

1. **Гриллинг до кода.** Стоимость ошибки в разговоре — минуты, в коде — часы. Каждый вопрос с вариантами и рекомендацией; граница знания фиксируется как «принято по умолчанию», а не прячется.
2. **Двухуровневая готовность.** «Г» (гейты зелёные) ≠ «Р» (пользователь увидел живой прогон). Этап не закрыт без обоих.
3. **Зелёные тесты исполнителя не принимаются.** Тесты пишет отдельная роль, атакует их отдельная роль; выжившая мутация = дыра.
4. **Гейт перед каждым коммитом.** Хук блокирует commit при красном lint/typecheck/test и при расхождении дерева с индексом — это enforcement, не договорённость.
5. **Связность.** Коммит-сообщение ссылается на пункт чек-листа: `CHECKLIST N.N — <что сделано>`; отчёт приёмки сохраняется в `docs/acceptance/` и линкуется из пункта; отметка `[x]` ставится в том же коммите, что и работа.
6. **Сессия заканчивается handoff'ом.** Свежая сессия не имеет контекста: «где остановился» — с точностью до файла, не «почти готово».

Скиллы — при наступлении триггера читай `<имя>/SKILL.md` и следуй ему. Каталог скиллов: **{{SKILLS_DIR}}**.

| Скилл | Когда |
|---|---|
| grilling | требования/план размыты, до реализации |
| spec-to-checklist | спека/архитектура → этапы с критериями Г/Р |
| tdd | работа тест-первым; справочник качества тестов |
| acceptance | единица кода объявлена готовой, до коммита |
| code-review | ревью диффа от фиксированной точки |
| research | изучить вопрос по первоисточникам |
| handoff | конец сессии / длинная сессия, передача контекста |
