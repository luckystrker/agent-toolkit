## Пайплайн разработки (agent-toolkit)

Карта: входящее → **triage** → идея → **research** → **grilling** → **domain-modeling** (PRD, ADR, тезаурус, философия) → **to-spec** (финишная черта) → [**formal-verification**, если инварианты про деньги/данные/конкурентность] → **spec-to-checklist** / **to-tickets** (доска) → **teamlead** раздаёт исполнителям (**tdd**) → проверка другой моделью: гейт → **interrogate** → **acceptance** → коммит (гейт-хук) → **release-train** (замер скорости, глаза на проде) → **handoff**. Сбоку: **blast-radius** (что заденет), **code-review**, **judge** (до любого вопроса владельцу), **correct** (поймать поправку владельца), **reflect** (еженедельно), **create-verification-skill**, **model-bench**.

Правила конвейера:

1. **Гриллинг до кода.** Ошибка в разговоре стоит минуты, в коде — часы. Вопрос — с вариантами и рекомендацией; граница знания фиксируется как «принято по умолчанию».
2. **Двухуровневая готовность.** «Г» (гейты зелёные) ≠ «Р» (живой прогон с артефактом). Этап не закрыт без обоих.
3. **Слова — не доказательство.** «Тесты зелёные», «я проверил», «должно работать» не принимаются. Доказательство — запись экрана по сценарию, цифры до/после, состояние базы после действия.
4. **Проверяет другой.** Тесты пишет и атакует не исполнитель; принимает другой агент на **другой модели** в свежем контексте; выжившая мутация = дыра. Исполнитель не переводит свой тикет в done.
5. **Скрипты прежде слов.** Гейт (линтеры, сложность, тесты, TLC) перед каждым коммитом — хук, не договорённость. Пока скрипты красные, агент код не оценивает. Обходить проверки (`--no-verify`, `core.hooksPath`) агенту запрещено.
6. **Риск = частота (1–5) × вред (1–10).** Деньги и данные — вред 10. < 5 → каталог `docs/known-issues.md`; ≥ 5 → чинить; вред 10 → человек.
7. **Опасное подтверждает человек.** Деньги, люди, необратимое, доступы — всегда владельцу; защищённые пути гейта и `human: required` в тикетах. Остальные вопросы — сначала `judge` (цитата прошлого решения), владельцу — только новое.
8. **Общение агентов.** Виден отправитель (`--as`), лимит на пинг-понг, общая доска `tasks/` и лог `.agents/events.jsonl` (`node .agents/bin/board.mjs`).
9. **Связность.** Коммит: `CHECKLIST N.N — <что сделано>` (проверяет commit-msg-хук; обход — `[no-checklist]`); отчёт приёмки — `docs/acceptance/`; `[x]` — в том же коммите; новое требование — в бэклог, не молча в код.
10. **Поправка владельца — сразу в `.agents/lessons/inbox.md`** (`correct`). Еженедельно `reflect` превращает уроки в архитектуру, линтер, тест или хук; слово в AGENTS.md — последним.
11. **Медленнее на 10 % — не выкатываем** (`release-train`, `.agents/bin/bench-compare.mjs`).
12. **Сессия заканчивается handoff'ом**: «где остановился» — с точностью до файла; взятые тикеты освобождены.

Пересечения триггеров — по порядку конвейера, один скилл за раз: идея → `grilling` → `domain-modeling` → `to-spec`; нарезка для человека — `spec-to-checklist`, для агентов — `to-tickets` (после чек-листа, не вместо); «готово» → `interrogate` (артефакты) → `acceptance` (тесты и мутации) → `code-review` (дифф целиком, по запросу); вопрос владельцу → сначала `judge`, пакет входящих — `triage`.

Скиллы — при наступлении триггера читай `<имя>/SKILL.md` и следуй ему. Каталог скиллов: **{{SKILLS_DIR}}**.

| Скилл | Когда |
|---|---|
| triage | входящие баги/запросы → оценка, решения владельца пакетом, очередь |
| research | изучить вопрос по первоисточникам |
| grilling | требования/план размыты, до реализации |
| domain-modeling | PRD, ADR, тезаурус, философия проекта |
| to-spec | спека с финишной чертой и сценариями приёмки |
| formal-verification | инварианты → TLA+ → мутанты → тесты → TLC в гейте |
| spec-to-checklist | спека → этапы с критериями Г/Р |
| to-tickets | спека/чек-лист → тикеты на доске для агентов |
| teamlead | координация исполнителей; роли и модели (`.agents/roles.md`) |
| tdd | работа тест-первым; справочник качества тестов |
| blast-radius | что заденет изменение; нужен ли человек |
| interrogate | кто-то сказал «готово» — потребовать артефакты |
| acceptance | тестировщик → критик (мутации) → гейт, до коммита |
| create-verification-skill | научить агентов запускать приложение и снимать доказательства |
| code-review | ревью диффа от фиксированной точки |
| judge | у агента вопрос к владельцу — сначала сюда |
| correct | владелец поправил/отругал — записать дословно |
| reflect | еженедельная рефлексия: уроки → принуждение |
| release-train | выкатка: гейт → замер скорости → прод → глаза на проде |
| model-bench | выбрать модели на роли по своим задачам |
| handoff | конец сессии, передача контекста |
