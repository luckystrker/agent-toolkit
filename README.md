# agent-toolkit

Рабочий набор скиллов, гейтов и инструментов для **агентской фабрики**: от входящего
бага или идеи до кода на проде — и еженедельного обучения фабрики на поправках владельца.
**Harness-agnostic**: базовые механизмы (AGENTS.md-индекс + git-хуки + CLI-инструменты на Node)
работают в любом агенте, нативные интеграции включаются там, где они есть.

## Пайплайн

```
входящее → triage ─┐
идея → research → grilling → domain-modeling → to-spec ─→ [formal-verification]
                                                   │
                         spec-to-checklist / to-tickets (доска tasks/*.md)
                                                   │
                     teamlead ─→ исполнители (tdd) ─→ проверка ДРУГОЙ моделью:
                                                      гейт → blast-radius → interrogate → acceptance
                                                   │
                             git commit (гейт-хук) ─→ release-train (замер скорости, глаза на проде)
сбоку: judge (до вопроса владельцу) · correct (поправка владельца) · reflect (каждое воскресенье)
       code-review · create-verification-skill · model-bench · handoff (конец сессии)
```

Подробно, со схемами доверия, ролей и общения агентов: [docs/pipeline.md](docs/pipeline.md).
Что нового в 3.0 — [CHANGELOG.md](CHANGELOG.md).

## Скиллы

| Этап | Скилл | Что делает |
|---|---|---|
| Откуда работа | `triage` | входящие баги и запросы → оценка частота × вред → решения владельцу пакетом → очередь |
| Идея → спека | `research` | ресёрч по первоисточникам со ссылками |
| | `grilling` | интервью по одному вопросу до границы знания владельца |
| | `domain-modeling` | PRD, ADR, тезаурус (одно понятие — одно имя), философия проекта |
| | `to-spec` | спека с финишной чертой: каждый пункт — с типом доказательства |
| | `spec-to-checklist` | этапы для человека с критериями «Г» (гейты) и «Р» (живой прогон) |
| | `to-tickets` | тикеты для агентов на общей доске: водопад или параллель |
| Инварианты | `formal-verification` | инварианты словами → TLA+ → мутанты краснеют → тесты на коде → TLC в гейте |
| Роли | `teamlead` | план, раздача исполнителям, приёмка; код не пишет; роли → модели |
| | `model-bench` | выбор моделей на роли по своим задачам, а не по рейтингам |
| Реализация | `tdd` | тест-первым; швы, антипаттерны тестов |
| Доказательства | `blast-radius` | что заденет изменение, нужен ли человек |
| | `interrogate` | на каждое «готово» — артефакт: запись экрана, цифры до/после, состояние базы |
| | `acceptance` | тестировщик → критик с исполненными мутациями → гейт |
| | `create-verification-skill` | один раз научить агентов запускать приложение и снимать доказательства |
| | `code-review` | ревью диффа по двум осям: стандарты и спека |
| В прод | `release-train` | гейт → замер скорости (−10 % = стоп) → прод → глаза на проде |
| Владелец | `judge` | ответ агенту дословной цитатой прошлого решения; новое — владельцу |
| Обучение | `correct` | поправку владельца — сразу и дословно в уроки |
| | `reflect` | еженедельно: уроки → архитектура / линтер / тест / хук, слово последним |
| Сессия | `handoff` | передача контекста следующей сессии |

## Совместимость

Три слоя: **AGENTS.md-индекс** (секция-диспетчер + скиллы в репо — читает любой агент),
**нативные скиллы** (автозагрузка в родной каталог harness'а), **гейт** (git-хук —
базовое принуждение; PreToolUse-адаптеры — опционально, ради статуса в интерфейсе).

|---|---|---|---|---|
| Claude Code | ✅ | ✅ `~/.claude/skills` + субагенты оркестратора | ✅ | ✅ `--claude-hook` (проект или глобально) |
| ZCode | ✅ | ✅ `~/.zcode/skills` | ✅ | ✅ `--zcode-hook` |
| Codex | ✅ | ✅ `~/.codex/skills` | ✅ | — |
| OpenCode | ✅ | ✅ (в т.ч. `.agents/skills` в проекте) | ✅ | — (свой плагинный API) |
| Pi | ✅ | через `--skills-dir` | ✅ | — (extensions) |
| Antigravity | ✅ | через `--skills-dir` | ✅ | — (Rules) |
| Qoder | ✅ (rules совместимы с AGENTS.md) | через `--skills-dir` | ✅ | — (Quest Mode) |
| Devin | ✅ (лимит 16 КиБ на весь AGENTS.md) | — (облако) | ✅ в его песочнице | — |

## Глобально для Claude Code: CTO-оркестратор в любом проекте

```bash
node install.mjs --claude-hook --profile
```

После этого любой проект, открытый в Claude Code, работает по конвейеру из коробки:

| Что | Куда | Зачем |
|---|---|---|
| 21 скилл | `~/.claude/skills/` | конвейер доступен везде |
| Правила конвейера + роль CTO-оркестратора + профиль | `~/.claude/CLAUDE.md` (маркированные секции, свои правила не трогаются) | главная сессия планирует, раздаёт, принимает по доказательствам |
| Роли фабрики: `executor` — OpenCode на DeepSeek V4.1 Flash; `verifier`, `tester`, `critic` — OpenCode на Muse Spark 1.3; усилие high | `~/.agent-toolkit/roles/` + `factory.json` | код пишет исполнитель в своём worktree, проверяет другая модель |
| Доска, замер скорости, запуск ролей (`factory.mjs`) | `~/.agent-toolkit/bin/` | работают в любом git-репозитории |
| Гейт на `git commit` | `~/.claude/settings.json` → `~/.agent-toolkit/gate/pre-commit` | проверки перед каждым коммитом агента, запрет обхода |

Оркестрация — средствами bb: `factory.mjs spawn <роль>` создаёт дочерний bb-тред с моделью,
провайдером и окружением роли из `factory.json` (исполнитель — новый git worktree,
проверяющие — окружение исполнителя); bb будит оркестратора итогом каждого треда.
Исполнители не коммитят: после вердикта проверяющего коммит в worktree делает оркестратор —
через глобальный гейт — и вливает ветку. Модели меняются правкой `factory.json`
(для проекта — `.agents/factory.json`, только изменённые поля); проверяющий на модели
исполнителя скрипт не запустит.

Как ведёт себя оркестратор: вопросы и мелкие правки делает сам; фичи, неясные баги и
многофайловую работу — через исполнителей-треды и независимую проверку; деньги, данные, доступы,
пуш и деплой — только с согласия владельца. В новом проекте без настроенных проверок на первой
нетривиальной задаче он предложит настроить гейт.

Глобальный гейт определяет репозиторий по самой команде (`cd X && git commit`, `git -C X commit`),
не путает с коммитом текст в heredoc и строках, в проекте со своим git-хуком тулкита не
дублирует прогон. Проект без настроенных проверок проходит с предупреждением, но обход
(`--no-verify`, подмена хуков) блокируется везде.

Обновление — повторный запуск той же команды; откат — `node install.mjs --remove`
(чужие хуки и свой текст в CLAUDE.md сохраняются). Полная установка в проект (`--project`)
поверх глобальной добавляет git-хуки для любых коммитов (не только агентских), проверку
ссылки на чек-лист и скиллы для других агентов.

## Установка

Node ≥ 18, без зависимостей.

```bash
# универсально: скиллы → <проект>/.agents/skills/, секция → AGENTS.md,
# git-хуки (гейт + проверка ссылки на чек-лист) → <проект>/.githooks/ (+ core.hooksPath)
node install.mjs --project C:/projects/my-project
# + .agents/bin/board.mjs и bench-compare.mjs (доска и замер скорости — только в project-режиме)

# то же + адаптеры статуса (по желанию, гейт они не дублируют по сути —
# это один и тот же gate/pre-commit, но блокирует до запуска команды)
node install.mjs --project C:/projects/my-project --zcode-hook --claude-hook

# пользовательский режим: скиллы + пайплайн-секция во все НАЙДЕННЫЕ harness'ы
# (claude / zcode / codex / opencode — по наличию их домашних каталогов)
node install.mjs

# то же + профиль-секция в пользовательские файлы инструкций
node install.mjs --profile

# Pi / Qoder / Antigravity — явный каталог:
node install.mjs --skills-dir ~/.pi/skills
```

Посмотреть план без изменений: добавь `--dry-run`. Откатить: `--remove` (с теми же флагами;
для проектного режима — `--remove --project <путь>`). Изменённые файлы перед перезаписью
копируются в `~/.agent-toolkit/backups/<дата>/`.

**Новый клон проекта:** настройка `core.hooksPath` живёт в локальном `.git/config`, а не в
репозитории — в каждом новом клоне (включая облачных агентов вроде Devin) выполни один раз
`node install.mjs --project .` или добавь в package.json `"prepare": "node install.mjs --project ."`.

## Как запустить фабрику в проекте

1. **Установка:** `node install.mjs --project <путь> --claude-hook` (адаптер — для своего
   harness'а). В проекте появятся `.agents/skills/`, `.agents/bin/`, `.githooks/`, секция в `AGENTS.md`.
2. **Гейт:** скопируй `adapters/gate.json.example` в `<проект>/.agents/gate.json` и впиши
   команды проверок проекта и защищённые пути (деньги, касса, миграции). Для npm-проекта
   достаточно скриптов `lint`/`typecheck`/`complexity`/`test`/`tlc` в package.json.
3. **Роли и модели:** попроси агента «будь тимлидом» — скилл `teamlead` создаст
   `.agents/roles.md` из шаблона и покажет на подтверждение.
4. **Первая фича:** «поспрашивай меня про <идею>» → дальше агент идёт по конвейеру сам:
   гриллинг → тезаурус и ADR → спека → тикеты → исполнители → проверка → коммит.
5. **Доказательства:** один раз — «сделай скилл проверки» (`create-verification-skill`),
   чтобы любой агент умел поднять приложение и снять запись/цифры/состояние базы.
6. **Регулярное:** в планировщике harness'а — `triage` дважды в день, `reflect` по воскресеньям.

Доска агентов (`.agents/bin/board.mjs`, полная справка — `board help`):

```bash
B="node .agents/bin/board.mjs"
$B list                                    # тикеты; READY — можно брать
$B claim 7 --as exec-1                     # взять (атомарно, с учётом зависимостей)
$B status 7 review --as exec-1             # отдать на проверку
$B status 7 done --as verifier-1           # принять может только ДРУГОЙ агент
$B msg teamlead "вопрос" --as exec-1       # сообщение; пинг-понг ограничен
$B events --tail 20                        # общий лог: кто что сделал
```

Замер скорости перед выкаткой: `node .agents/bin/bench-compare.mjs bench/current.json` —
сравнение с `.agents/bench-baseline.json`, медленнее больше чем на 10 % — exit 2.

## Гейты качества

`gate/pre-commit` — один файл, два режима:

- **git pre-commit** (базовый): git вызывает файл сам — проверка обязательна
  независимо от того, кто коммитит: агент, человек из терминала, IDE, скрипт-обёртка.
- **PreToolUse-адаптер** (ZCode/Claude Code): читает JSON-payload из stdin, гейтит
  только `git commit` и **запрещает агенту обходить проверки**: `--no-verify`/`-n`,
  подмену `core.hooksPath`, самоодобрение через `AGENT_TOOLKIT_HUMAN_APPROVED`.

Порядок: (1) рабочее дерево = индекс (расхождение — блок с подсказкой `git add -A`);
(2) **защищённые пути** из `.agents/gate.json: protected` — необратимое (деньги, касса,
внешние системы, миграции): коммит только с `AGENT_TOOLKIT_HUMAN_APPROVED=1`, который
выставляет человек; (3) гейты по порядку, fail-fast, таймаут на каждый (120 с, настраивается).

Гейты — **любые команды** из `.agents/gate.json: gates` (Python, Go, Rust — что угодно),
иначе npm-скрипты `lint → typecheck → complexity → test → tlc`, какие объявлены.
Пример — `adapters/gate.json.example`. Нет ни того, ни другого — проход **с явным
предупреждением** (fail-open объявлен, а не молча). Коды: 0 = пропустить, 2 = блокировать.

`gate/commit-msg` — правило связности: если в корне есть `CHECKLIST.md`, сообщение
коммита содержит `CHECKLIST N.N` (merge/revert/fixup проходят; осознанный обход —
`[no-checklist]`). Нет `CHECKLIST.md` — хук неактивен.

Ограничения, названные честно:
- `git commit --no-verify` из терминала отключает git-хуки. У агента адаптер ловит
  `--no-verify` и его сокращения, `-n`, подмену `core.hooksPath`, самоодобрение — это
  защита от **случайного** обхода; команду можно спрятать в скрипт, адаптер видит только
  текст. Без адаптера (Codex, OpenCode, Pi, …) запрет обхода — правило в AGENTS.md.
- `AGENT_TOOLKIT_HUMAN_APPROVED` и `board --as human` (требует интерактивный терминал) —
  растяжки против ошибок агента, не защита от злоумышленника: `--as` — заявление, а не
  аутентификация, TTY можно эмулировать. Настоящий жёсткий шлюз для необратимого —
  защита веток и обязательное ревью владельца на сервере (CODEOWNERS, branch protection).
- Неотслеживаемые файлы блокируют коммит намеренно (тесты видят файл, коммит — нет).
  Рантайм доски (`.agents/events.jsonl`, `tasks/.locks/`) исключён и сам себя gitignore'ит;
  лог событий поэтому локален для машины, не история проекта.
- Невалидный `package.json` роняет хук в Node ещё до его кода (exit 1, стек Node) —
  коммит всё равно блокируется, но сообщение не наше.
- Существование отчёта приёмки, артефактов и отметки `[x]` — конвенция скиллов без автопроверки.
- Пример TLA+ в `formal-verification` проверяется тестом `tests/tla.test.mjs` (оригинал проходит TLC, мутант нарушает инвариант), но только при наличии Java и `TLA2TOOLS=<путь к tla2tools.jar>`; без них тест пропускается.

## Изменение и распространение

- Правки вносишь здесь — это канонический источник; установленное обновляется
  повторным запуском установщика (изменённое бэкапится с датой).
- Новые скиллы: папка `skills/<имя>/SKILL.md` (frontmatter: name, description) —
  установщик подхватит автоматически; добавь строку в индекс `agents/pipeline-section.md`.
- Исполняемый слой (гейт, доска, бенч, установщик) покрыт тестами: `npm test`.
  Проверка примера TLA+ настоящим TLC включается так:
  `TLA2TOOLS=<путь к tla2tools.jar> JAVA=<путь к java> npm test` (без них тест пропускается).
- Версия — в `install.mjs`, `package.json` и [CHANGELOG.md](CHANGELOG.md); `node install.mjs --version`.
