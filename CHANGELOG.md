# Changelog

## 3.0.0 — агентская фабрика

От конвейера одной сессии — к фабрике из нескольких агентов: откуда берётся работа,
как агенты делят её и общаются, кто и чем доказывает готовность, как работа едет
в прод и как фабрика учится на поправках владельца.

### Новые скиллы (14)

- **Откуда работа:** `triage` — входящее → частота × вред → решения владельца пакетом → очередь (водопад/параллель).
- **От идеи к спеке:** `domain-modeling` (PRD, ADR, `thesaurus.md`, `philosophy.md` + шаблоны),
  `to-spec` (спека с финишной чертой и сценариями приёмки), `to-tickets` (тикеты на общей доске).
- **Инварианты до кода:** `formal-verification` — инварианты словами → TLA+ → мутанты модели
  краснеют → property-тесты на живом коде → TLC в гейте.
- **Роли:** `teamlead` (план и приёмка, код не пишет; `roles-template.md` — роли → модели,
  проверяет всегда другая модель, усилие high), `model-bench` (модели на своих задачах).
- **Это не доказательство:** `interrogate` (артефакт на каждое утверждение), `blast-radius`
  (что заденет изменение, нужен ли человек), `create-verification-skill` (проектный скилл
  запуска приложения и съёмки доказательств).
- **Поезд в прод:** `release-train` — гейт → замер скорости (10 %) → прод → глаза на проде;
  необратимое — через детерминированный шлюз и человека.
- **Судья вкуса:** `judge` — решено (дословная цитата) / вопрос неверный / новое (владельцу);
  деньги, люди, необратимое, доступы — всегда владельцу; калибровка вслепую ≥ 90 %.
  Шаблон журнала `docs/decisions.md`.
- **Фабрика учится:** `correct` (поправка владельца — сразу и дословно в
  `.agents/lessons/inbox.md`), `reflect` (еженедельно: уроки → архитектура/линтер/тест/хук,
  слово последним; старое — в архив).

### Инструменты (`tools/` → `<проект>/.agents/bin/`)

- `board.mjs` — общая доска `tasks/*.md` и общий лог `.agents/events.jsonl`: атомарный claim
  (lock O_EXCL), водопад по `depends_on`, исполнитель не принимает свою работу,
  `executor_model ≠ verifier_model`, `human: required` закрывает только человек,
  сообщения между агентами с обязательным отправителем и лимитом пинг-понга.
- `bench-compare.mjs` — замеры против базовой линии, регрессия > 10 % → exit 2.

### Гейт

- Настраиваемые гейты `.agents/gate.json: gates` — любые команды; **снято ограничение
  «только npm-проекты»**.
- Стандартный npm-набор расширен: `lint → typecheck → complexity → test → tlc`.
- Защищённые пути `.agents/gate.json: protected` (семантика .gitignore) — коммит в них
  только с одобрением человека (`AGENT_TOOLKIT_HUMAN_APPROVED=1`).
- В режиме PreToolUse-адаптера агенту запрещено обходить проверки: `--no-verify`/`-n`
  (вне кавычек сообщения), подмена `core.hooksPath`, самоодобрение.
- Битый `gate.json` — блок, а не проход вслепую.

### Изменения существующего

- Секция-диспетчер: полная карта фабрики, 12 правил (слова — не доказательство; проверяет
  другая модель; скрипты прежде слов; шкала риска; опасное — человеку; общение агентов;
  поправки → принуждение; порог скорости), индекс 21 скилла.
- `acceptance`: шаг 0 «скрипты прежде критиков», проверка другой моделью, доказательства
  по финишной черте (`interrogate`), вердикт по шкале частота × вред.
- `code-review`: гейт до ревью, тезаурус как стандарт имён, оценка риска находок.
- `grilling`: голосовые заметки и research на входе, выход в `domain-modeling` → `to-spec`,
  решения владельца — в журнал решений.
- `tdd`: `docs/thesaurus.md`, инварианты как property-тесты. `spec-to-checklist`: артефакт
  в критерии «Р», переход к `to-tickets`. `handoff`: освобождение взятых тикетов, проверка поправок.
- Профиль: что делает владелец — вкус, удаление, амбиции; агенты ждут владельца, а не наоборот.
- Установщик: доставка и откат `.agents/bin/`; данные фабрики (`tasks/`, лог, уроки,
  решения) при `--remove` не трогаются.
- Тесты тулкита: `npm test` (гейт, доска, бенч, установщик; без зависимостей).
  Пример TLA+ проверяется настоящим TLC (`TLA2TOOLS=<jar> npm test`): исправлен ложный
  deadlock в исходном примере (`CHECK_DEADLOCK FALSE` для законного конца протокола).

### По независимому ревью (Sonnet 5.5, методика developing-ai-agents)

Каждая воспроизведённая находка закрыта регрессионным тестом (32 теста + TLC):
- доска: `done` только из `review` и не исполнителем (раньше `claimed → done` проходил);
  роли не отменяют правило разных моделей; `--as human` — только интерактивный терминал;
  парсер не теряет block-YAML молча (ошибка), понимает CRLF, сохраняет комментарии,
  пишет атомарно; битый тикет не ломает всю доску; lock упавшего агента снимается;
  `inbox` не теряет сообщение, пришедшее во время чтения; доска общая для всех git
  worktree; разделитель `--` и ошибка на неизвестный флаг; рантайм сам себя gitignore'ит;
- гейт: защищённые пути ловят переименование и не-ASCII имена (`--no-renames -z`);
  `protected`/`gates` не-массивом — блок; адаптер ловит `--no-verif`, склейку кавычками,
  чужой `--help` в той же строке; рантайм доски не считается расхождением дерева;
- bench: нулевая базовая линия больше не прячет регрессию;
- судья: цитата проверяется `grep -F`; калибровка на отложенной выборке ≥ 30 с интервалом
  Уилсона, результат — отдельно от журнала решений; `correct`: пересказ помечается и не
  цитируется; `reflect`: принуждение доказывается падением на исходном случае, срок
  пересмотра правил, лимит своих правил в AGENTS.md;
- диспетчер: порядок для пересекающихся триггеров; шаблон verify-скилла вынесен в файл.

### Несовместимости

- Проекты с npm-скриптами `complexity` или `tlc` теперь гоняют их в гейте.
- Агентские `git commit --no-verify` / `-n` блокируются адаптером.

## 2.0.1 — фиксы по независимому ревью

### Гейт

- **Полиглот CJS/ESM**: `gate/pre-commit` и `gate/commit-msg` написаны без
  static import/require (динамический `import()` внутри async-функции) — файл без
  расширения обязан работать и как CJS, и как ESM в зависимости от `"type"` в
  package.json проекта. До фикса в проектах с `"type":"commonjs"` хук молча
  не исполнялся, на Node < 22.7 падал; теперь заявление «Node ≥ 18» честное.
- **Бит исполнения**: установщик делает `chmod 0o755` обоим хукам после
  копирования — без него git на POSIX молча пропускает хук; в индексе тулкита
  файлам проставлен exec bit.
- Исключение `git help commit` из матчинга payload-режима (раньше справка
  ложно гоняла полный гейт).

### Новый commit-msg-хук (`gate/commit-msg`)

Принуждение правила конвейера №5: при наличии `CHECKLIST.md` в корне сообщение
коммита должно содержать `CHECKLIST N.N` (merge/revert/fixup — автоматически;
осознанный обход — `[no-checklist]`). Без чек-листа хук неактивен.

### Установщик

- **Схема Claude Code исправлена**: адаптер пишется в `hooks.PreToolUse` без
  чужеродного `events`; `--remove` теперь действительно удаляет адаптер из
  `.claude/settings.json` (раньше запись оставалась смотреть на удалённый файл)
  и вычищает опустевшие структуры.
- **core.hooksPath не теряется**: прежнее значение (husky/lefthook) сохраняется
  в манифест с предупреждением при установке и восстанавливается при `--remove`.
- `--instructions` с путём вне проекта пишется по прямому пути (раньше —
  мусорный файл внутри проекта из-за строкового сравнения префиксов).
- `--remove` больше не сжимает пустые строки за пределами своих секций.
- `--instructions` работает и в user-режиме; при доставке скиллов без
  секции-диспетчера (`--skills-dir` без целей инструкций) — явное предупреждение.

### Скиллы

- `acceptance`: протокол мутаций защищён от потери незакоммиченного кода —
  перед мутацией `git add <файл>` (индекс = точка восстановления), откат
  `git checkout --` возвращает до-мутационное состояние; покрытие ≥ 80%
  измеряется coverage-инструментом проекта, при его отсутствии — качественная
  оценка с пометкой «экспертная».
- `tdd`: убрано делегирование рефакторинга скиллу code-review (в нём этой
  стадии нет); рефакторинг — отдельный шаг после зелёного.
- README/pipeline: правило №5 честно разделено на проверяемое (формат ссылки —
  commit-msg-хук) и конвенцию (отчёт, отметка `[x]`); задокументирован обход
  `--no-verify`.

## 2.0.0 — harness-agnostic редизайн + фиксы ревью

Совместимость: Claude Code, ZCode, Codex, OpenCode, Pi, Antigravity, Qoder, Devin.

### Архитектура

- **Универсальный слой** для всех harness'ов: скиллы в проекте (`.agents/skills/`,
  нативно сканируется OpenCode), секция-диспетчер пайплайна в `AGENTS.md`
  (маркированная, идемпотентно обновляется), git-хук гейта как базовое
  принуждение (`core.hooksPath .githooks`).
- **Нативные слои** опционально: пользовательские каталоги скиллов
  (`~/.claude`, `~/.zcode`, `~/.codex`, `~/.config/opencode` — по детекции),
  PreToolUse-адаптеры ZCode/Claude Code (`--zcode-hook`, `--claude-hook`).
- Профиль и пайплайн-секция **вставляются маркированными секциями**, а не
  заменой файла целиком.

### Гейт (`gate/pre-commit`, был `hooks/pre-commit-gate.mjs`)

- Один файл, два режима: git pre-commit (напрямую) и PreToolUse-payload из stdin.
- Git-хук закрывает обход текстового матчинга скриптом-обёрткой.
- **Fail-fast**: первый упавший гейт останавливает прогон.
- **Таймаут 120 с на каждый гейт** (watch-режим тестов больше не съедает бюджет молча).
- **Сверка дерева с индексом**: расхождение (правки не в индексе, untracked) блокирует
  коммит — гейт проверяет именно то, что коммитится.
- Нет package.json / гейт-скриптов — проход **с явным предупреждением** в stderr
  (fail-open объявлен, ранее — молча).

### Скиллы

- `acceptance`: мутации обязаны **исполняться** (применил → прогнал → откатил
  `git checkout`), выжившая мутация = дыра; фиксированные шаблоны промптов
  тестировщика и критика; отчёт приёмки — файл `docs/acceptance/<этап>.md`,
  ссылка из чек-листа; тестировщику передаются согласованные швы; убран
  персональный триггер; harness-agnostic (есть субагенты — изоляция, нет —
  последовательные проходы с пометкой пониженных гарантий).
- `research`: бюджет времени (~15 мин, проверить статус, не ждать молча),
  пометка происхождения данных в шаблоне отчёта.
- `tdd`: согласованные швы передаются тестировщику явно.
- `spec-to-checklist`: конвенция коммитов `CHECKLIST N.N` + ссылка на отчёт приёмки.
- Все скиллы: упоминания инструментов конкретных harness'ов заменены на
  capability-формулировки (инструмент выбора вариантов, субагенты, веб-поиск).

### Установщик

- `--dry-run` (план без изменений), `--remove` (откат по манифесту
  `~/.agent-toolkit/manifest.json`), датированные бэкапы изменённого в
  `~/.agent-toolkit/backups/<дата>/` (перезапись не молчит и не теряет правки).
- Слияние с существующими PreToolUse-конфигами: **дописывает** свою запись в
  массив, а не «не трогаю конфиг» при чужих хуках (иллюзия включённого гейта).
- `--version`; версия и CHANGELOG ведутся явно.

### Прочее

- Убрана проект-специфика (упоминания конкретного проекта-прародителя).
- Правила пайплайна доставляются в контекст агента (секция AGENTS.md), а не
  живут только в документации тулкита.
