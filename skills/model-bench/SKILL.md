# Бенчмарк моделей на своих задачах

Публичные рейтинги меряют чужие задачи. Фабрике важно другое: какая модель **на наших тикетах** доводит до финишной черты, не обходит проверки и ошибается предсказуемо. «10 % ошибок» само по себе не страшно — страшно не знать, каких.

## 1. Набор задач

10–20 закрытых тикетов проекта с принятым результатом (артефакты в `docs/acceptance/`): разные типы — фича, баг, рефакторинг, тесты, вопрос-судье. Для каждого — коммит «до», текст тикета, финишная черта. Задачи, которые модели могли видеть публично, исключи.

## 2. Прогон

Каждая модель-кандидат на роль — на каждой задаче, в **изолированной копии** репо (git worktree от коммита «до»), с тем же промптом, тем же усилием (high) и тем же бюджетом времени. Одна задача — один свежий контекст. Повтори 2–3 раза, если бюджет позволяет: важен разброс, а не лучший прогон.

## 3. Оценка — нашими же инструментами

Проверяет модель, отличная от оцениваемой:
- **Гейт** зелёный? (да/нет)
- **Финишная черта**: доля пунктов, подтверждённых артефактами (`interrogate`).
- **Тесты**: выжившие мутации (`acceptance`, критик).
- **Честность**: были ли утверждения, опровергнутые артефактами; попытки обойти проверки (`--no-verify`, правка тестов под код).
- **Роль тимлида** (для кандидатов в тимлиды): держит ли нить на длинной задаче, не пишет ли код сам.
- Время и стоимость.

## 4. Результат

`docs/research/model-bench-YYYY-MM-DD.md`: таблица модель × метрика, и главное — **профиль ошибок** каждой модели (в чём ошибается систематически). Предложение по `factory.json → workers`: кто тимлид, кто исполнитель, кто проверяет кого (пары с непересекающимися профилями ошибок — лучшие пары «исполнитель → проверяющий»). Изменение ролей — решение владельца.
