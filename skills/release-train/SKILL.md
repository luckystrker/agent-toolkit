# Поезд в прод

```
кандидат → гейт → замер скорости → прод → глаза на проде
необратимое (деньги, касса, внешние системы) → жёсткий шлюз: код без ИИ + человек
```

Поезд ходит по расписанию и с одними и теми же остановками: никакой «срочный фикс» не едет в обход.

## 1. Кандидат

Конкретный коммит/тег, а не «текущая ветка». Все тикеты в нём — `done` (принятые другой моделью, с артефактами); пункты чек-листа отмечены. Запиши SHA — дальше все проверки про него.

## 2. Гейт

Тот же гейт, что на коммите (`.githooks/pre-commit`: линтеры, сложность/CRAP, тесты, TLC), плюс медленное, что не гоняется на каждом коммите (e2e, интеграционные). Красный — поезд стоит, без обсуждений.

## 3. Замер скорости

1. Прогони бенчмарк проекта на кандидате (сценарии из радиуса поражения + горячие пути). Результат — JSON «метрика → число» (см. формат в `.agents/bin/bench-compare.mjs`).
2. `node .agents/bin/bench-compare.mjs bench/current.json` — сравнение с `.agents/bench-baseline.json`.
3. **Медленнее больше чем на 10 % — не выкатываем** (exit 2). Не «в пределах шума», не «потом оптимизируем»: либо чиним, либо владелец явно меняет базовую линию (`--update-baseline`) с записью в `docs/decisions.md`.
4. Замеры — на одной и той же машине/окружении; первый прогон выбрасывается (прогрев); каждую метрику — медиана из ≥ 5 прогонов.

Нет бенчмарка в проекте — скажи об этом прямо; предложи тикет на его создание. Без замера поезд едет только с пометкой владельца «без замера».

## 4. Необратимое: жёсткий шлюз

Если кандидат трогает защищённые пути (`.agents/gate.json: protected` — деньги, касса, внешние системы, миграции с удалением):
- проверка — **детерминированный код без ИИ**: скрипт сверки (суммы до/после, контрольные транзакции в песочнице, dry-run миграции на копии), его результат — да/нет;
- выкатку подтверждает **человек**: дифф защищённых путей + результат шлюза + план отката. Агент готовит пакет, но не нажимает кнопку.

## 5. Прод

Командой деплоя проекта (из AGENTS.md / verify-скилла). Постепенно, если инфраструктура умеет (сначала часть трафика). Записать: время, SHA, кто подтвердил.

## 6. Глаза на проде

Сразу после выкатки и через оговорённое время (например, 1 час):
- те же сценарии приёмки на проде (только безопасные, без необратимых действий) — с артефактами;
- метрики прода против значений до релиза: ошибки, время ответа, ключевые бизнес-счётчики;
- логи на новые ошибки.

Хуже — откат по плану, затем разбор (урок через `correct`/`reflect`). Отчёт о поезде — `docs/releases/YYYY-MM-DD-<sha>.md`: кандидат, гейт, замер (таблица из bench-compare), шлюз, кто подтвердил, глаза на проде.
