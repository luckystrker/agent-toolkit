# Допрос: это не доказательство

| Не доказательство | Доказательство |
|---|---|
| «Тесты зелёные» | Запись экрана по сценарию из спеки |
| «Я проверил» | Цифры до и после (замер, счётчик, время ответа) |
| «Должно работать» | Состояние базы / внешней системы после действия |

Принимает **другой агент, другая модель, свежий контекст**. Если тебя запустили в той же сессии, что писала код, — скажи это в отчёте: гарантии понижены.

## Вход

Отчёт исполнителя (или его сообщение «готово»), тикет/пункт спеки с финишной чертой и сценариями, радиус поражения (если делался), дифф.

## Процесс

1. **Разложи отчёт на утверждения.** Каждое «сделал/проверил/работает/исправлено» — отдельная строка. Расплывчатое («всё ок», «основное работает») — тоже строка, с пометкой «неконкретно».
2. **Для каждого — вопрос «чем докажешь?».** Найди артефакт: файл записи, вывод команды, запрос в базу и его результат, скриншот, лог. Ссылка обязана открываться, а содержимое — соответствовать утверждению (запись показывает именно этот сценарий, цифры именно этой метрики, после именно этого действия).
3. **Нет артефакта — добудь сам**, если это дёшево: прогони сценарий (браузер/computer use/CLI — см. проектный verify-скилл, созданный `create-verification-skill`), сними цифры, сделай запрос в базу. Сохрани в `docs/acceptance/evidence/<тикет>/`.
4. **Не добыть — «не подтверждено».** Не «вероятно работает».
5. **Сверь с финишной чертой.** Каждый пункт: подтверждён артефактом / опровергнут / не подтверждён. Плюс сценарии из радиуса поражения.
6. **Противоречия.** Артефакт показывает не то, что заявлено, — это находка с оценкой риска (частота × вред), даже если «мелочь».

## Порядок «скрипты прежде слов»

Если гейт (линтер, сложность, тесты, TLC) красный — допрос не начинается: результат «возвращено, гейт красный», без оценки кода. Агент код не оценивает, пока скрипты красные.

## Вердикт

```markdown
## Допрос: <тикет>  (проверял: <агент/модель>, исполнитель: <агент/модель>)
| Утверждение | Артефакт | Статус |
|---|---|---|
| Сценарий S1 проходит | evidence/007/S1.mp4 | ✅ подтверждено |
| Ускорил список на 30 % | — | ⚠️ не подтверждено (замера нет) |
| Не трогал биллинг | git diff --stat: src/billing/x.ts | ❌ опровергнуто |
Находки (риск ≥ 5 — блок): …
Решение: принять / вернуть исполнителю (с причинами) / к человеку (необратимое)
```

Принять можно только если все пункты финишной черты ✅. Вернуть — `board status <id> claimed --as <ты> --note "<причины>"` или сообщением исполнителю.
