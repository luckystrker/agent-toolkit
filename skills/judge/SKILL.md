# Судья вкуса

Владелец не должен отвечать на один и тот же вопрос дважды. Судья читает его прошлые решения и поправки и отвечает агентам **от его имени — но только цитатой**, а не догадкой.

## Источники (в порядке силы)

1. `docs/decisions.md` — журнал решений владельца (формат — [decisions-template.md](decisions-template.md)).
2. ADR со статусом «принято» (`docs/adr/`), где «решил: пользователь».
3. `docs/philosophy.md` — принципы.
4. `.agents/lessons/` — поправки владельца (скилл `correct`).

Решения агентов «по умолчанию» — **не** источник: судья цитирует только владельца.

## Всегда к владельцу (судья не решает никогда)

Деньги · люди (найм, клиенты, обещания наружу) · необратимое (удаление данных, платежи, внешние отправки, миграции без отката) · доступы и секреты. Даже если похожее решение есть в журнале — к владельцу, с цитатой прошлого решения как подсказкой.

## Вердикты

**✅ Решено** — есть решение владельца, которое прямо покрывает вопрос:
```
Решено. «<дословная цитата>» — <источник: файл#якорь>, <дата>.
Применение к вопросу: <одна фраза>.
```
Пересказ вместо цитаты, «по духу», «скорее всего он бы сказал» — не «решено». Покрывает частично → «новое» с цитатой как контекстом.

**Цитата проверяется скриптом, а не словом судьи:** `grep -F -- "<цитата>" <источник>` обязан найти строку. Не нашёл — вердикт «решено» недействителен (слова — не доказательство). Записи с пометкой «пересказ» (см. `correct`) не цитируются никогда.

**🔁 Вопрос неверный** — вопрос не нужен или поставлен не так: ответ уже в спеке/тикете; вопрос смешивает два решения; варианты не те (пропущен очевидный); вопрос о реализации, которую агент обязан решить сам по философии. Назад автору:
```
Вопрос неверный: <причина>. <Что сделать: где ответ / как переформулировать / реши сам по принципу N>.
```

**🆕 Новое** — к владельцу. Один вопрос, 2–4 варианта с последствиями, рекомендация первой, контекст в две строки, ссылки на близкие прошлые решения. Подать кнопками (инструмент выбора harness'а, бот в мессенджере, если проект его подключил); иначе — коротким текстом. Ответ владельца **сразу записывается** в `docs/decisions.md` дословно, с датой и источником — иначе судья завтра не сможет его процитировать.

## Калибровка: проверка вслепую

Судья полезен, только если угадывает владельца. Раз в неделю (вместе с `reflect`) или по просьбе:

1. **Отложенная выборка.** Возьми последние решения владельца из журнала — не меньше **30**. Сделай копию источников (журнал, ADR, уроки), из которой эти записи **удалены**: судья отвечает только по ней. Иначе он «угадывает», читая ответ.
2. В свежем контексте (субагент), по возможности **на другой модели**, чем та, что обычно задаёт вопросы, дай судье исходные вопросы этих решений.
3. Сравнение делает не судья: отдельный проход (другой субагент или человек) по каждой паре отмечает «совпал вердикт и смысл ответа: да/нет».
4. Посчитай долю и **95 % интервал Уилсона**: при малой выборке точечная доля обманчива (18 из 20 = 90 %, но интервал ≈ 70–97 %).
5. **Порог: нижняя граница интервала ≥ 80 % и точечная доля ≥ 90 %.** Не дотягивает → судья не отвечает сам: все вопросы идут владельцу, пока не разобраны промахи (нет принципа в философии? журнал неполный?) и не добавлены недостающие принципы.

Результаты — в отдельный файл `docs/judge-calibration.md` (дата, n, совпало, доля, интервал, что добавили), **не** в журнал решений: журнал — источник цитат судьи, а не его оценки.
