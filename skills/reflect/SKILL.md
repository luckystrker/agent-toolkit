# Рефлексия: фабрика учится каждую неделю

```
мои реакции → агенты-сборщики → грабли и уроки → новые скиллы и AGENTS.md → старое в историю
     ↑                                                                            │
     └──────────────────────────── каждое воскресенье ─────────────────────────────┘
```

**Правило уходит в архитектуру, линтер, тест или хук. Слово идёт последним.** Инструкция в AGENTS.md — самое слабое принуждение: её забывают, обходят, теряют при сжатии контекста. Если урок можно превратить в проверку, которая падает, — превращай.

## 1. Сбор (сборщики — параллельные субагенты, если harness умеет)

За период с прошлой рефлексии (дата — в `.agents/lessons/README.md` или последнем архиве):
- `.agents/lessons/inbox.md` — поправки владельца;
- `docs/decisions.md` — новые решения;
- `.agents/events.jsonl` — тикеты, вернувшиеся из review (`board events`), эскалации, лимиты пинг-понга;
- отчёты `docs/acceptance/`, `interrogate`, `code-review` — находки, выжившие мутации;
- блокировки гейта, если проект их логирует; откаты релизов.

Каждый сборщик возвращает факты со ссылками, без выводов.

## 2. Грабли и уроки

Сгруппируй факты: одна и та же ошибка в разных обличьях = одни грабли. Для каждых:
- **Что повторяется** (с числом случаев и ссылками).
- **Корень**: не хватало знания (→ тезаурус/философия/скилл), процесс позволил (→ гейт/доска), модель систематически ошибается (→ roles.md / model-bench).
- **Урок** — одной фразой, проверяемо.

## 3. Принуждение — самый сильный уровень

| Уровень | Когда | Пример |
|---|---|---|
| Архитектура | ошибку можно сделать невозможной | тип `Money` вместо `number`; модуль, без которого не вызвать платёж |
| Линтер | ошибка видна в тексте кода | правило запрета импорта, запрет `any`, порог сложности |
| Тест | ошибка видна в поведении | регрессионный тест, property-тест инварианта |
| Хук | ошибка видна в процессе | гейт, защищённый путь, проверка формата коммита |
| Слово | ничего выше не применимо | строка в AGENTS.md / скилле |

Каждое предложение — пользователю на одобрение пакетом (как в `triage`): «урок → уровень → конкретное изменение». Одобренное реализуется обычным конвейером (тикет → исполнитель → проверка), не напрямую рефлексией.

**Доказательство, что принуждение работает:** линтер/тест/хук сначала прогоняется на исходном случае из урока (тот самый коммит или кусок кода) и обязан **упасть** — как мутант. Не падает — урок не закрыт.

**Гигиена памяти:**
- у каждого правила — дата, ссылки на исходные записи, срок пересмотра (по умолчанию 3 месяца);
- противоречащие уроки не сливаются молча — оба к владельцу одним вопросом;
- записи «пересказ» сначала подтверждаются владельцем, потом становятся уроками;
- **лимит:** собственные правила проекта в AGENTS.md (вне секции agent-toolkit) — не больше ~40 строк. Упёрлись — сначала перевести правило в проверку или удалить, потом добавлять.

## 4. Скиллы и AGENTS.md

- Повторяющийся многошаговый процесс → новый скилл (проектный, `.agents/skills/`) или правка существующего.
- Слово в AGENTS.md — короткое, с датой и ссылкой на урок. Секцию agent-toolkit не трогай (её перезаписывает установщик) — свои правила вне маркеров.
- Урок, уже превращённый в линтер/тест/хук, **убирается** из AGENTS.md: двойное принуждение — шум в контексте.

## 5. Старое в историю

- Обработанные записи inbox → `.agents/lessons/archive/YYYY-MM-DD.md` (с пометкой, во что превратились).
- Правила, которые за месяц ни разу не сработали, и костыли под прошлую модель — кандидаты на удаление: предложи владельцу («удаление» — одна из его трёх работ).
- Обнови дату рефлексии в `.agents/lessons/README.md`.

## 6. Калибровка судьи

Прогони проверку вслепую из скилла `judge`. < 90 % — урок «судья не угадывает X» в этот же отчёт.

## Отчёт владельцу

Грабли (топ-5 по повторяемости) → что предлагается и на каком уровне → что удаляется → точность судьи. Без пересказа недели.

Регулярность: настрой планировщик harness'а (cron/автоматизация) на воскресенье — скилл описывает одну итерацию.
