# Создать проектный скилл проверки

Допрос (`interrogate`) и приёмка требуют артефактов. Чтобы их добыть, агенту нужно уметь **запустить приложение и пройти сценарий как пользователь** — а это знание специфично для проекта. Этот скилл один раз выясняет его и записывает в `.agents/skills/verify-<проект>/SKILL.md`, после чего любой агент (другая модель, свежий контекст) проверяет без вопросов.

## 1. Разведка (сам, по репо)

- Как поднимается: команды из README/package.json/Makefile/docker-compose; порты; нужные переменные окружения и где взять тестовые значения (без реальных секретов в файле).
- Данные: как получить чистое тестовое состояние (сиды, фикстуры, отдельная БД), как сбросить.
- Интерфейсы: веб (URL), десктоп, CLI, API, бот.
- Где смотреть состояние: доступ к БД (команда запроса), логи, админка, внешние песочницы (платёжные — только тестовый режим).
- Чем снимать доказательства в этом окружении: браузерная автоматизация/computer use harness'а (скриншоты, запись), `ffmpeg`/системная запись экрана, `curl` + сохранение ответа, SQL-запрос до/после.

Что не выяснил из репо — вопрос пользователю по правилам гриллинга (по одному, с вариантами).

## 2. Пробный прогон

Подними приложение и пройди один реальный сценарий из спеки целиком, сохранив каждый тип артефакта. Не получилось — чини инструкцию, пока не получится. Скилл без успешного пробного прогона не записывается.

## 3. Запиши скилл

`.agents/skills/verify-<проект>/SKILL.md` — по шаблону [verify-template.md](verify-template.md): поднять, чистое состояние, пройти сценарий, доказательства (запись, цифры до/после, состояние базы), ловушки.

Добавь строку о нём в индекс скиллов проекта (AGENTS.md, рядом с секцией agent-toolkit — вне её маркеров, иначе установщик её перезапишет).

## Правила

- Никаких реальных секретов и боевых данных в файле скилла и в артефактах.
- Необратимые действия (реальные платежи, письма клиентам) в сценариях проверки запрещены — только песочницы и тестовые режимы; если без них никак — сценарий проверяет человек.
