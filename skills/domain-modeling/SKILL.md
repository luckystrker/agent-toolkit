# Моделирование домена: PRD, ADR, тезаурус, философия

Агенты ломают проект не столько кодом, сколько словами: «заказ», «корзина» и «чек» в трёх модулях означают одно и то же, а «пользователь» — три разных вещи. Этот скилл фиксирует **язык** и **решения** до спеки, чтобы спека, тикеты, тесты и код говорили одинаково.

Вход: итог гриллинга (решения / принято по умолчанию / неизвестное) и отчёты research. Нет итога гриллинга — сначала `grilling`.

## Артефакты

Все в `docs/` проекта (или где указано в AGENTS.md). Шаблоны — рядом с этим файлом: [thesaurus-template.md](thesaurus-template.md), [philosophy-template.md](philosophy-template.md), [adr-template.md](adr-template.md), [prd-template.md](prd-template.md).

1. **`docs/thesaurus.md` — тезаурус.** Одно понятие = одно каноническое имя. Для каждого: определение одной фразой простыми словами, имя в коде (тип/таблица/модуль), запрещённые синонимы, связи с другими понятиями. Конфликт имён в коде и документах — не решай молча: вопрос пользователю с вариантами.
2. **`docs/philosophy.md` — философия.** 5–10 принципов, которые решают спорные компромиссы без пользователя («простота важнее гибкости», «данные клиента не теряются никогда, даже ценой отказа»). Каждый принцип — с примером решения, которое он предписывает. Это корм для скилла `judge`.
3. **`docs/prd/<slug>.md` — PRD.** Что и для кого, проблема, сценарии пользователя, нефункциональные требования (скорость, объёмы, надёжность), что НЕ входит. Без технологий, если пользователь сам их не выбрал.
4. **`docs/adr/NNNN-<slug>.md` — ADR** на каждое решение, которое дорого отменить: контекст, рассмотренные варианты, решение, последствия (что станет проще / труднее), дата, кто решил (пользователь или «агент по умолчанию»). Статус: принято / заменено ADR-NNNN. Старые ADR не переписываются — заменяются новым.

## Процесс

1. Выпиши все существительные и глаголы из итога гриллинга, PRD-черновика и (если есть код) имён типов/таблиц. Сгруппируй синонимы — это кандидаты в тезаурус.
2. По каждой группе с расхождением — один вопрос пользователю (правила гриллинга: варианты + рекомендация). Остальное заполни сам.
3. Из ответов гриллинга, которые меняют архитектуру или дорого откатываются, — ADR. Из повторяющихся «почему так» — принципы философии.
4. PRD собирается последним: он уже говорит языком тезауруса.
5. Покажи пользователю краткое резюме: N понятий, M ADR, принципы списком. Спроси, переходить ли к `to-spec`.

## Правила

- Существующие файлы **дополняй**, не переписывай. Изменение определения в тезаурусе — с датой и причиной в конце статьи.
- Термин в тезаурусе — с бытовым пояснением: пользователь читает эти файлы.
- Тезаурус — источник правды для имён в тестах (`tdd`), спеке (`to-spec`) и ревью (`code-review`, ось «Стандарты»).
