# Спека с финишной чертой

Спека — договор между владельцем и фабрикой. Главное в ней — **финишная черта**: проверяемое снаружи условие «готово», которое агент не может «объявить», а может только **показать артефактом**.

Вход: PRD, ADR, тезаурус (скилл `domain-modeling`), итог гриллинга. Нет — сначала они; дыры не выдумывай, а помечай вопросом.

## Структура `docs/spec/<slug>.md`

````markdown
# Спека: <название>          (ссылки: PRD, ADR-NNNN, тезаурус)

## Цель
<одна фраза: что изменится для пользователя>

## Финишная черта
Готово, когда ВСЕ пункты подтверждены артефактами (не словами):
- [ ] <наблюдаемое поведение> — артефакт: <запись экрана сценария N | цифры до/после | состояние базы после действия | лог>
- [ ] Скорость не хуже базовой линии больше чем на 10 % (bench-compare)
- [ ] Инварианты I1…In доказаны моделью и покрыты тестами (если есть раздел «Инварианты»)

## Сценарии приёмки
### S1. <название>
- Дано: <состояние, данные>
- Действие: <что делает пользователь — по шагам, чтобы агент мог воспроизвести через computer use / браузер / CLI>
- Ожидается: <что видно на экране / в ответе>
- Доказательство: <какой артефакт сохранить и где: docs/acceptance/evidence/<slug>/S1.*>

## Инварианты
- I1. <что истинно всегда, словами: «сумма по счетам не меняется при переводе»>
  (затем — скилл formal-verification, если инвариант про конкурентность, деньги или данные)

## Поведение при ошибках
- <что пользователь видит, что сохраняется, что откатывается>

## Необратимое
- <деньги, касса, внешние системы, удаление данных> → защищённые пути гейта (`.agents/gate.json: protected`), приёмка человеком

## Не входит
## Вопросы к спеке
````

## Правила

- Имена — только из тезауруса. Новое понятие → сначала в тезаурус.
- Каждый пункт финишной черты **наблюдаем снаружи** и имеет тип артефакта. «Код написан», «тесты зелёные», «работает» — не пункты (это не доказательство).
- Сценарии написаны так, чтобы их прогнал **другой агент** с нуля — без знания реализации.
- Необратимое перечислено явно — по нему ставятся защищённые пути и `human: required` в тикетах.
- Покажи пользователю финишную черту отдельно и спроси подтверждение: это то, по чему будет приниматься работа.

Дальше: `spec-to-checklist` (этапы для человека) и/или `to-tickets` (тикеты для агентов на доске).
