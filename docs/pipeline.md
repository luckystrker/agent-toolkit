# Пайплайн: агентская фабрика

Как компоненты тулкита работают вместе — от входящего бага или идеи до кода на проде
и еженедельного обучения фабрики. Harness-agnostic: скиллы, гейт и инструменты
работают в Claude Code, ZCode, Codex, OpenCode, Pi, Antigravity, Qoder, Devin (матрица — в README).

## 1. Откуда берётся работа

```
чаты / issues / баги ─→ triage ─→ частота × вред ─→ да/нет владельцу ─→ очередь (доска)
                        (сам)      (< 5 → каталог)   пакетом, кнопками    водопад | параллель
```

`triage` собирает входящее, склеивает дубликаты, оценивает риск и приносит владельцу
только решения — одним пакетом (например, дважды в день по расписанию harness'а).
Одобренное становится тикетами (`to-tickets`). В сам конвейер владелец почти не вмешивается.

## 2. От идеи к спеке

```
голос/текст ─→ research ─→ grilling ─→ domain-modeling ─→ to-spec ─→ spec-to-checklist / to-tickets
               рынок,       вопрос за    PRD, ADR,           финишная    этапы Г/Р     тикеты на доске
               open source  вопросом     thesaurus.md,       черта,
                                         philosophy.md       сценарии
```

- **Тезаурус** (`docs/thesaurus.md`) — одно понятие = одно имя во всех документах, тестах и коде.
- **Философия** (`docs/philosophy.md`) — принципы, которые решают компромиссы без владельца; корм для судьи.
- **Финишная черта** спеки — проверяемые снаружи пункты, у каждого тип артефакта.

## 3. Инварианты до кода (`formal-verification`)

```
инварианты словами ─→ модель TLA+ ─→ мутанты модели краснеют ─→ property-тесты на живом коде ─→ TLC в гейте
```

Для фич с деньгами, данными и конкурентностью без формальной проверки код не принимается —
это часть Definition of Done. TLC подключается гейтом (`npm run tlc` или строка в `.agents/gate.json`).

## 4. Роли и общение агентов (`teamlead`, `to-tickets`, `.agents/bin/board.mjs`)

```
CTO (владелец / его агент) — решения, приёмка по цели
  └─ тимлид — план и приёмка, код не пишет
       ├─ исполнитель × N  ──→  проверка: ДРУГАЯ модель, свежий контекст
```

Роли (что делать) зашиты в `factory.mjs`; агенты (кто делает: харнесс + модель) — в `factory.json` → `workers`. Проверяет всегда другая
модель; усилие high везде; модели выбираются бенчмарком на своих задачах (`model-bench`).

Пять схем общения агентов и что из них даёт тулкит:

| Схема | В тулките |
|---|---|
| Родитель и субагенты | скиллы acceptance, code-review, research, teamlead (инструмент субагентов harness'а) |
| Общая доска `tasks/*.md` — кто что взял | `board.mjs claim/status/list/next` — атомарный claim, водопад по `depends_on` |
| Сообщения через CLI | `board.mjs msg/inbox` — отправитель обязателен, лимит пинг-понга |
| Общий лог событий (стигмергия) | `.agents/events.jsonl` — каждое действие с отправителем, `board.mjs events` |
| Сетевые протоколы (A2A, HTTP, JSON-RPC) | нет — для агентов на разных машинах; локально хватает доски и CLI |

Всегда: видно отправителя, лимит на пинг-понг, опасное подтверждает человек.

Доска проверяет: в `done` — только из `review` и не исполнителем; при указанных
`executor_model`/`verifier_model` они обязаны различаться (без исключений для ролей);
`human: required` закрывает только `--as human`, а он требует подтверждения в
интерактивном терминале. Битый тикет помечается в `list`, а не ломает доску; lock упавшего
агента снимается сам. **Честно:** `--as` — заявление, а не аутентификация; доска защищает
от ошибок и забывчивости агентов, а не от намеренного обмана.

## 5. Схема доверия

```
СКРИПТЫ ──────────────→ КРИТИКИ ЛОМАЮТ ──────────→ ВЕРДИКТ
линтеры                 другая модель               частота (1–5) × вред (1–10)
сложность / CRAP        свежий контекст             < 5 → каталог known-issues
тесты                   mutation testing            деньги и данные: вред 10
TLC по модели           property-based testing
```

Пока скрипты красные, агент код не оценивает: гейт идёт первым в `acceptance`,
`interrogate`, `code-review`.

**Это не доказательство:** «тесты зелёные», «я проверил», «должно работать».
**Доказательство:** запись экрана по сценарию, цифры до и после, состояние базы после
действия. Принимает другой агент, другая модель, свежий контекст —
`blast-radius` (что проверять) → `interrogate` (артефакты на каждое утверждение) →
`acceptance` (тестировщик → критик с исполненными мутациями). Чтобы любой агент мог
добыть артефакты, проект один раз получает свой verify-скилл (`create-verification-skill`).

## 6. Гейт (`gate/pre-commit` → `.githooks/pre-commit`)

1. Рабочее дерево = индекс (проверяется то, что коммитится).
2. Защищённые пути (`.agents/gate.json: protected`) — только с одобрением человека.
3. Гейты по порядку, fail-fast: `.agents/gate.json: gates` (любые команды) или npm-скрипты
   `lint → typecheck → complexity → test → tlc`.
4. В режиме PreToolUse-адаптера агенту дополнительно запрещено обходить проверки:
   `--no-verify`/`-n`, подмена `core.hooksPath`, самоодобрение `AGENT_TOOLKIT_HUMAN_APPROVED`.

`gate/commit-msg` — ссылка `CHECKLIST N.N` при наличии `CHECKLIST.md`.

## 7. Поезд в прод (`release-train`)

```
кандидат → гейт → замер скорости → прод → глаза на проде
необратимое (деньги, касса, внешние системы) → жёсткий шлюз: детерминированный код + человек
```

Медленнее на 10 % — не выкатываем: `.agents/bin/bench-compare.mjs` сравнивает замеры
с `.agents/bench-baseline.json` и возвращает exit 2.

## 8. Судья вкуса (`judge`)

```
вопрос агента → судья читает решения и поправки владельца → ✅ решено (дословная цитата, источник, дата)
                                                           → 🔁 вопрос неверный (назад автору с причиной)
                                                           → 🆕 новое (владельцу кнопками)
всегда владельцу: деньги, люди, необратимое, доступы
```

Журнал решений — `docs/decisions.md`. Проверка вслепую на прошлых ответах: меньше 90 %
верных — судья не отвечает сам.

## 9. Фабрика учится каждую неделю (`correct`, `reflect`)

```
мои реакции → сборщики → грабли и уроки → новые скиллы и AGENTS.md → старое в историю
   ↑ (correct: сразу, дословно, в .agents/lessons/inbox.md)                 │
   └──────────────────────────── каждое воскресенье (reflect) ─────────────┘
```

Правило уходит в архитектуру, линтер, тест или хук. Слово в AGENTS.md — последним.

## 10. Что делает владелец

Вкус («нет», даже если работает), удаление (костыли под прошлую модель), амбиции
(×100, а не +2 %). Не владелец ждёт агентов, а агенты ждут владельца — это зашито
в профиль (`profile/AGENTS-user.md`).

## Правила конвейера

Двенадцать правил доставляются в контекст каждого агента секцией-диспетчером
в AGENTS.md (`agents/pipeline-section.md`) — конвейер живёт не только в документации.

## Применимость

Пайплайн генеричен: стек-специфичны только команды гейтов (`.agents/gate.json` или
npm-скрипты), бенчмарк проекта и проектный verify-скилл.
